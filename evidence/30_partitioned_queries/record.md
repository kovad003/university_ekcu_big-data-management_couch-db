## Interpretation

- Both endpoints answered the same one-store question with the same complete set of ids, checked over all bookmark pages and against a client-side filter.
- The partitioned query is limited to one partition by construction (/_partition/<store>/_find) and uses the partitioned index. The global query must consider every shard of the database.
- Queries across stores (C5) need a global view. In the partitioned database they need a separate global index, or they fall back to scanning.
- A partition groups related documents (all of one store's orders) so they are stored together. On this single node it does not show physical distribution across servers, and no speed-up is claimed.
